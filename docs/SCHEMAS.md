# Odin input schemas (for document authors)

Every contract, the company context file and every event email must follow these formats. The parser,
citations and "View references" highlighting depend on them.

## 1. Contract documents (PDF or DOCX)

### Cover block (first lines, one `KEY: value` per line)
```
CONTRACT TITLE: Master Cloud Services Agreement
CONTRACT ID: MSA-2026-001            ← unique; used in citations and in event emails
CONTRACT TYPE: vendor | lease | employment | saas | partnership | nda | supply | other
EFFECTIVE DATE: 2026-02-01           ← ISO date preferred
PARTY A: Acme Analytics Pvt Ltd (the "Customer")   ← PARTY A MUST be our company
PARTY B: Nimbus Cloud Ltd (the "Provider")         ← PARTY C, D… allowed
GOVERNING LAW: Singapore
VERSION: 1                           ← bump when you upload an updated version
SUPERSEDES: (optional) MSA-2025-004
```

### Body: numbered clauses
```
1. SERVICES                         ← top level: number + dot + UPPERCASE heading
1.1 The Provider shall …            ← sub-clauses: 1.1, 1.1.1 (max 4 levels)
2. TERM AND RENEWAL
2.1 …
SCHEDULE A - PAYMENT TERMS          ← SCHEDULE / ANNEX / ANNEXURE / EXHIBIT / APPENDIX + id, uppercase
```

Rules:
- Type clause numbers as literal text. Do not use Word auto-numbering, because it is lost when LibreOffice is
  not installed. The Docker image does include LibreOffice.
- Start each clause on its own line, with the number at the beginning of that line.
- Top-level numbers go up by one (1., 2., 3.). Do not skip any.
- Write money with a currency (`INR 4,50,000`, `USD 12,000`, `$12,000`, `₹2,50,000`).
- Use a text PDF. Scanned image PDFs are not supported because there is no OCR.

Include these clauses wherever they apply: term, renewal and notice window, payment schedule, late-payment
interest, SLA and service credits, liability cap, indemnity, termination (for convenience and for cause, with
notice), confidentiality, compliance or data protection, governing law, dispute resolution, assignment, force
majeure, exclusivity.

Plant these for the demo: one vague term ("reasonable time"), one missing value ("rate in Schedule B" where
Schedule B does not exist), one internal contradiction (two notice periods), and one one-sided indemnity.
Also plant cross-contract conflicts: exclusivity against a second supplier, governing-law mismatch, a
downstream SLA stricter than the upstream SLA, and a lease ending before a dependent service.
`corpus/samples/contracts/*.docx` (generated by `scripts/make_samples.py`) is a working example of all of this.

## 2. Company context (`.md`, `.txt`, `.pdf` or `.docx`)
```
COMPANY NAME: Acme Analytics Pvt Ltd
INDUSTRY: B2B retail analytics SaaS
HQ / JURISDICTIONS: Bengaluru, India; IN, SG, UK
FISCAL YEAR START: 04-01
BASE CURRENCY: INR
RISK APPETITE: low | medium | high
APPROVAL THRESHOLD: INR 10,00,000     ← actions above this always need human approval
KEY CONTACTS: legal@acme.example, cfo@acme.example
STRATEGIC PRIORITIES: free text
CRITICAL DEPENDENCIES: free text (which contracts/vendors the business depends on)
```

## 3. Event emails (Heimdall live feed)
Send these to the company Gmail account that is logged in to Odin.
```
Subject: [ODIN-EVENT] <EVENT_TYPE> <CONTRACT_ID|ALL>

EVENT_ID: EVT-0007                       (optional; prevents duplicates)
EVENT_TYPE: PAYMENT_LATE                 (required)
OCCURRED_AT: 2026-11-03T10:30:00+05:30   (required, ISO 8601; moves the sim clock forward)
CONTRACT_ID: MSA-2026-001                (or ALL / comma list / UNKNOWN)
COUNTERPARTY: Nimbus Cloud Ltd           (optional)
AMOUNT: INR 2,50,000                     (optional)
REFERENCE: Invoice INV-2231              (optional)
SEVERITY_HINT: low|medium|high           (optional, not trusted)
DESCRIPTION:
Free text until the end of the mail.
```
`EVENT_TYPE` is one of: PAYMENT_MADE, PAYMENT_LATE, PAYMENT_MISSED, INVOICE_RECEIVED, SERVICE_OUTAGE,
SLA_BREACH, DELIVERY_LATE, DELIVERY_RECEIVED, REGULATORY_CHANGE, PRICE_CHANGE, TERMINATION_NOTICE_RECEIVED,
RENEWAL_NOTICE_RECEIVED, PARTY_CHANGE, FORCE_MAJEURE, DISPUTE_RAISED, CUSTOM.

How an email is handled:
1. A strict parser reads it first.
2. If that fails, an LLM fallback tries (it must reach at least 0.6 confidence).
3. If both fail, the event is rejected and the sender gets an auto-reply containing this template.

Odin only reads emails whose subject starts with `[ODIN-EVENT]`. Processed emails get the Gmail label
`ODIN/processed`. Ready-made examples are in `corpus/samples/emails/`.

## 4. Internal data models
All of these are in `backend/odin/core/models.py`. That file is the single source of truth, and the
