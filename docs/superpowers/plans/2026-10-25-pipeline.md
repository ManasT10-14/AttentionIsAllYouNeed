# Evaluation and Security Pipeline Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver backend-independent DeepEval, security and optional LangSmith plumbing now, ready for actual product mappings later.

**Architecture:** An async adapter returns typed execution/evidence records. Independent evaluators produce explicit statuses; the runner isolates failures and writes redacted JSON. Optional integrations load lazily and never fabricate evidence.

**Tech Stack:** Python 3.11, Pydantic 2, HTTPX, pytest; optional DeepEval, LangSmith and LangGraph.

**Spec:** `docs/architecture-proposal.md`, with the user's authorization to implement the pipeline now and defer product decorators.

## Global Constraints

- No paid calls or external trace uploads without explicit config enablement.
- No real security side effects by default; no retries.
- Missing/partial evidence must not establish a successful negative security assertion.
- Keep product code independent; no assumed graph node names or API shape.
- Work in this directory: no Git repository exists, so Git/worktree/commit helpers do not apply.

## Review Focus

- A failing adapter or metric must not lose unrelated results.
- Credentials and synthetic protected canaries must not enter persisted reports or traces.
- Partial trajectories may prove an observed violation, but cannot prove absence of violations.
- Missing/disabled required checks and empty selections must not produce a green CI exit.
- Judge input must come from actual retrieval and judge instances must not share mutable state.
